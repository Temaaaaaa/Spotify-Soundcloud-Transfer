# Архитектура и восстановление

Приложение рассчитано на один локальный процесс и один аккаунт назначения. `server/index.ts` поднимает Express на `127.0.0.1`, выдаёт состояние интерфейсу и защищает изменяющие запросы проверками Origin и CSRF. `src/App.tsx` показывает шесть шагов и состояние сохранённого журнала.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `server/auth.ts`, `server/spotify-token.ts` | Раздельные OAuth flow, callback и хранение токенов. Spotify: Authorization Code + Basic client credentials; SoundCloud: PKCE S256 и отдельная логика обновления токена. |
| `server/http.ts`, `server/providers.ts` | HTTP, пагинация и адаптеры официальных API. Мутирующие запросы не повторяются вслепую. |
| `server/matcher.ts`, `server/aggressive.ts` | Поиск кандидатов и выбор сопоставлений. |
| `server/workflow.ts` | Снимок Spotify, резервная копия SoundCloud, discovery, план, исполнение и журнал Likes. |
| `server/playlist-verification.ts` | Сравнение полного read-back плейлиста с планом, отчёты о расхождениях и повторах. |
| `server/storage.ts` | Атомарная запись JSON через временный файл рядом с целевым, `fsync`, ограниченные повторы rename и восстановление совместимых временных файлов. |

## Состояние на диске

`.env` содержит настройки OAuth и токены Spotify. `data/` содержит токены SoundCloud, снимок, discovery, backup, план, checkpoints операций и audit. Оба пути исключены из Git. Снимок, завершённый discovery, backup и план служат основанием переноса; журнал операций меняется по мере работы. Публиковать эти файлы нельзя: они содержат сведения об аккаунтах и библиотеке.

Сохранение JSON пишет полный временный файл в той же директории, синхронизирует и закрывает его, затем заменяет canonical-файл. Временные ошибки Windows `EPERM`, `EACCES` и `EBUSY` повторяются с ограниченным backoff. При окончательном сбое старый checkpoint остаётся доступен, а временный файл сохраняется для восстановления. При запуске recovery сравнивает схему и привязку к исходному снимку; несовместимый или повреждённый файл не продвигается.

## Исполнение и возобновление

План привязан к хешу снимка Spotify и URN аккаунта SoundCloud. Перед записью приложение повторно проверяет эти привязки и наличие полной резервной копии. `SOURCE_PLAYLIST` должен пройти полную сверку количества и порядка треков. `LIKES_STAGING` — необязательный резервный артефакт: ранее созданный может остаться `PARTIAL`, а несозданный стать `SKIPPED`; переход к Likes зависит только от подтверждения исходных плейлистов.

Likes выполняются последовательно. Перед продолжением приложение читает текущие Likes и сверяет их с отдельным журналом, чтобы не отправить повторный POST для уже присутствующего трека. Состояние `RATE_LIMITED` ставится после подтверждённого HTTP 429 и хранит время обнаружения и возможное время повтора. Явное продолжение после истечения этого времени либо при его отсутствии переводит журнал в `RESUMING`; будущий `retryAt` удерживает очередь без записи. Ошибка хранения приостанавливает job, а не завершает сервер.

Запуск сервера сам по себе не запускает перенос. Тесты и сборка также не делают записей в SoundCloud.
