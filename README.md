# Spotify → SoundCloud Migrator

Локальное приложение для переноса плейлистов и понравившихся треков из Spotify в SoundCloud. Оно рассчитано на одного владельца двух аккаунтов, который хочет сохранить порядок плейлистов и иметь возможность продолжить перенос после остановки. Spotify используется только для чтения; изменения в SoundCloud начинаются после подтверждения переноса в интерфейсе.

Стек: Node.js 22.12+, TypeScript, Express, React и Vite. Приложение слушает только `127.0.0.1` и работает через официальные API провайдеров.

## Запуск

1. Установите Node.js 22.12+ и выполните `npm ci`.
2. Скопируйте `.env.example` в `.env` и заполните четыре значения `*_CLIENT_ID` и `*_CLIENT_SECRET`. Оставьте `PORT=3000`.
3. Добавьте в настройках приложений точные redirect URI:
   - Spotify: `http://127.0.0.1:3000/auth/spotify/callback`
   - SoundCloud: `http://127.0.0.1:3000/auth/soundcloud/callback`
4. Выполните `npm run dev` и откройте `http://127.0.0.1:3000`.

Spotify использует server-side Authorization Code flow с client secret. SoundCloud использует Authorization Code с PKCE S256. Токены Spotify хранятся в локальном `.env`, токены SoundCloud — в `data/tokens/`. Эти файлы исключены из Git; не копируйте их в issue, скриншоты или логи.

## Как проходит перенос

1. **Подключение:** авторизуйте оба аккаунта.
2. **Сканирование:** приложение сохраняет снимок Spotify и резервную копию SoundCloud. Это чтение API, без изменения библиотеки.
3. **Совпадения:** треки Spotify сопоставляются с доступными треками SoundCloud. Ненайденные позиции остаются в отчёте. В разделе «Дополнительно» можно выбрать обычный или строгий режим сопоставления.
4. **Подготовка:** создаётся план, привязанный к снимку Spotify и конкретному аккаунту SoundCloud. Здесь показываются объём переноса и пропуски.
5. **Перенос:** после явного подтверждения приложение создаёт приватные плейлисты, сверяет их состав и порядок чтением API, проверяет порядок Likes и переносит Likes последовательно. Прогресс записывается после операций.
6. **Готово:** интерфейс показывает итоговые счётчики и пропущенные треки.

Обычные плейлисты Spotify (`SOURCE_PLAYLIST`) требуют точной проверки состава и порядка. Вспомогательные `Spotify Likes 001/002/...` (`LIKES_STAGING`) служат резервной копией: их неполное создание не блокирует основной перенос Likes. Уже созданные вспомогательные плейлисты приложение не удаляет.

При остановке откройте приложение с тем же каталогом `data/` и нажмите **«Продолжить перенос»**. Журнал позволяет не создавать повторно подтверждённые плейлисты; перед новым Like приложение сверяет текущие Likes SoundCloud. Если SoundCloud ответил HTTP 429, перенос приостанавливается, а известное время повтора показывается в интерфейсе. Не удаляйте `data/` и `.env` между запусками.

## Проверки и диагностика

| Команда | Назначение |
| --- | --- |
| `npm test` | Автоматические тесты без записи в SoundCloud |
| `npm run build` | Проверка TypeScript и сборка интерфейса в `dist/` |
| `npm run dev` | Локальный сервер с Vite |
| `npm start` | Локальный сервер; отдаёт собранный интерфейс, если есть `dist/` |
| `npx tsx scripts/diagnose-discovery.ts` | Только читает локальный checkpoint discovery и временные файлы; печатает статус и счётчики без библиотеки и токенов |
| `npx tsx scripts/diagnose-playlist.ts` | Только GET к SoundCloud для первого неподтверждённого плейлиста; нужен действующий локальный токен, выводит технические URN |

Подробности устройства и правил возобновления: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Правила подготовки репозитория к публикации: [docs/PUBLISHING.md](docs/PUBLISHING.md).

## Ограничения

- Плейлист Spotify, недоступный текущему аккаунту для чтения, отмечается как неподдерживаемый источник и не обходится через неофициальные API.
- Совпадение треков по метаданным может выбрать другую версию записи. Перед началом переноса проверьте выбранный режим и счётчики.
- SoundCloud может не сохранить повторные вхождения одного URN в плейлисте. Такое изменение фиксируется в журнале; иные расхождения обычных плейлистов останавливают перенос.
- Локальные `data/` и `.env` содержат приватную информацию и не входят в репозиторий. Если перенос надо продолжить на другом компьютере, их переносите отдельно безопасным способом.
